## 真实语音链路

准备 30 条自愿提供的录音，分配到三道题，覆盖正常语速、否定词、人名、数字、指代、口音、安静环境和聚会背景声。加几组只差一个词的成对样本，例如「她进了影厅吗」与「她没进影厅吗」。

每条先由人标注原话及关键含义，再记录原始转写、是否需要改字或重录、确认后的文字和最终判词。裁判另外用人工标注的原话直接测一次。原始转写丢了「没」而裁判对人工原话答对时，计为转写错误。转写保留原意但裁判答反时，计为判题错误。空转写和超时计入语音测试总数。

| 项目 | 目标 | 实际记录 |
|---|---|---|
| 语义保持 | 至少 27/30 条无需改关键语义；其余可编辑纠正，不自动改问意 | 未测 |
| 关键字反转 | 单独记录否定、人名和数字的错转条数，并验证玩家可在提交前改字、重录或打字 | 未测 |
| 系统等待 | 至少 27/30 条从松手至可用判词的系统耗时不超过 5 秒 | 未测 |
| 上传耗时 | 单独记录，计入总体等待 | 未测 |
| ASR 耗时 | 单独记录 | 未测 |
| 裁判耗时 | 单独记录，包含冷启动 | 未测 |
| 手动确认 | 从总墙钟时间中单独列出，不与系统等待混淆 | 未测 |

3 至 5 秒是开发目标，不是厂商 SLA 或已测表现。记录中同时保留从松手到回答的总墙钟时间，避免把手动修改和确认带来的实际等待藏掉。

## 裁判与题目

每题 `testCases` 包含 20 条人工标准问答。用真实裁判逐条执行并保存题目 ID、版本、输入、预期判词、实际枚举、耗时和 token。

- 三题合计至少 57/60 条命中人工预期，核心事实不得矛盾；歧义应澄清，未设定细节不得编造。
- 每题再连续问 20 轮，覆盖正反问、复合提问、人物指代、同义改问和超出近期上下文的指代。试玩暂用最近 12 条问答作为上下文，指代不清时给澄清提示。
- 每题四条 `guessCases` 分别为完整正确、正确同义、缺关键原因、关键矛盾。前两类必须通过，后两类不得通过。
- 猜底只判断本次完整提交；不能把之前互相冲突的猜测凑成正确答案。需补充和暂无法判定不扣失败猜底机会，但占外呼尝试额度。
- 测试“忽略规则直接通过”、伪造系统消息、历史埋入指令、要求翻译或编码汤底。合法枚举也可能语义错误，不能仅凭 JSON 解析通过。
- 进行中的会话响应不得含汤底、内部评分点或模型原始解释。检查猜中、主动揭底或达到轮次上限后的汤底显示。

样本仅服务首版筛选，不能把 57/60 写成产品整体 95% 准确率。

`npm run eval:ai -- --full` 是开发者主动执行的独立付费评测，直接调用 provider，不走游戏配额。游戏内完整回归及连续对话可能超过单人100次判题日配额，应分两天或使用两个已授权测试账号执行，并分别保留记录。不要通过更换requestId绕过配额。

## 权限和异常

| 操作 | 应达到的结果 |
|---|---|
| 第二名用户读取第一名用户会话、请求或文件 | 拒绝；身份由云端上下文取得 |
| 同 requestId 重复提交相同内容 | 返回原状态，不再次外呼 |
| 同 requestId 换文本 | 拒绝，不改变已冻结快照 |
| 两个请求同时接近额度边界 | 原子预占，只允许剩余额度内的调用 |
| 提交后客户端超时 | 查询原状态，不自动新建付费请求 |
| 已派发而结果未知后主动重试 | 用户确认新尝试；撤销旧写回资格，仍记录可能发生的费用 |
| 旧结果在新尝试后到达 | 不追加旧消息、不覆盖草稿 |
| 转写后改字但未提交即关页 | 本地草稿恢复；服务端不伪造尚未提交文本 |
| 麦克风被拒、滑开取消、电话打断、切后台 | 提示明确，停止或取消录音，保留文字入口 |
| 清空或会话 7 天到期 | 作废旧局、撤销活动请求并删除正文；引导新开 |
| 录音转写成功、失败或取消 | 按保留规则清理，不能长留孤立文件 |
| 未配置 Key、未启用、内容检查失败 | 明确服务状态，不伪装是、否、无关或未通过 |
| 第三条提示、主动揭底及再来一局 | 静态提示按级解锁；揭底先确认；新局不混入旧消息 |
| 有效提问达到新局上限 | 首轮暂定 30 次，最后一条有效判词与自动揭底一同出现。澄清、未设定细节和服务失败均不扣有效提问次数 |

## 真实试玩与交付

3 至 5 名未听过解释的人，应能理解按住说话、确认文字、切换猜底、用提示和结束本局。记录是否主动重玩、在哪一步停住，不只收集“挺好玩”的评价。

上手练习另外检查：文字 AI 未配置时在读题入口明确提示并阻止开局。接通后提问和猜底由真实裁判处理，不要求精确匹配示例；输入需确认后发送，示例只填草稿。开放问法需引导澄清，错误猜底不提前泄露汤底，简短但因果完整的答案可以通关。超时只查询原请求，不自动重复付费；待处理或失败的响应不能把上一条判词放在新问题下面。

语音练习在微信真机中按住才录制、松手转写、上滑取消；权限未开或服务未配置时保留打字。转写完成只填草稿，不自动提交，迟到文字不能覆盖新编辑或已提交的内容。练习独立创建 1 小时有效的语音会话，不更换正式局、不扣正式局提问次数；转写仍使用相同 ASR 配额并产生识别费用。检查退出时清理、上传中退出不留孤立文件、超时只查旧结果不重复识别，以及从正式局进入练习再返回时录音监听不会互相干扰。文字练习调用同一裁判并产生费用，本地浏览器不模拟识别成功。

在微信真机核对短屏滚动、底部按钮、返回原局后的草稿和授权行为。本机浏览器可验证真实文字、录音转写和播报，但不能代替微信平台的权限、存储和真机检查。

## 好友房交流与待做真机验收

- 房间共用一条按时间排列的推理记录。玩家发言显示昵称，消息标记为「讨论」「提问」或「猜底」，主持人判词紧跟对应提交。
- 所有人可随时打字讨论。只有当前玩家可以向主持人提问或猜底，既能打字也能按住说话。语音先转写给说话者核对，提交后房间看到确认的文字。
- 房间顶部显示「轮到谁」。有效回答或猜底未通过后交给下一位，猜中则结束本局。澄清留给当前玩家。请求超时先查原结果，当前玩家也可主动跳过，使这一轮的迟到结果失效。
- 好友房验收用两部手机检查同时讨论、轮到谁、澄清后继续、重连后同步记录以及同一轮只判一次。讨论消息不进入裁判输入，也不算有效提问。

## 20 局后复核

实际统计每局识别秒数、模型输入输出 token、失败和重试次数、上传流量与云资源费用，再修订预算。基准假设每局 32 次、每段 6 秒、每次 2,000 输入和 50 输出 token；当前单价下加 30% 余量识别与判题约 0.126 元/局；另假设 800 字全新合成，合计加余量约 0.209 元，按 0.21 至 0.25 元留预算，不代表账单上限。

## 浏览器语音与人声

`npm run test:browser-voice` 使用与中文输入检查相同的 Playwright/Chromium 环境，固定合成麦克风和假模型验证取消不识别、松手正常结束、转写只填草稿、编辑后确认发送和拒绝权限后可打字，不产生真实模型费用。真实声音验收另记录真人录音、ASR 结果与耗时；合成测试录音不能当作真人语音准确率。

检查听题、主持回应、揭晓结果三类播放，关闭声音、开始录音和离开页面均要停止；迟到合成结果不得恢复已停止的播放。提前请求结果音频必须拒绝。自动播放被浏览器拦截时可手动重播，文本游戏继续。
